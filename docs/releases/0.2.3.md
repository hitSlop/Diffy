# Diffy 0.2.3 release plan

The release includes grouped Git worktrees, a fixed project header with window dragging, per-checkout review state, and Snake in empty diff panes. The landing page describes these features alongside existing project customization and review controls. Full gix replacement and SSH review remain isolated studies.

## Source and validation

- Commit on `waiting-snake` and open a PR against `master`.
- Run formatting, the complete `ui-tests` suite, Clippy with warnings denied, and unsigned macOS packaging.
- Build the website both with checkout disabled and with the CI fixture checkout URL. Review the page at desktop and mobile widths.
- Confirm the local bundle launches from `dist/Diffy.app`, worktree tabs and ⌘← / ⌘→ switch checkouts, text inputs retain cursor navigation, and the project header moves the window.
- Let the PR's macOS and website checks pass, then review and merge.

## Release artifacts

After merge, check out the exact source commit to release and run the validation gates again if it differs from the validated PR head. Build the signed artifacts using the existing workflow in [RELEASING.md](../../RELEASING.md):

```sh
python3 scripts/release-macos.py
```

This signs and notarizes the app and DMG, verifies the signed update archive on isolated app copies, and creates the versioned DMG, fixed-name download DMG, update archive/signature, manifest, and checksums under `dist/release`. Inspect their versions and launch the notarized app before tagging that validated source commit `v0.2.3` and preparing a GitHub draft release with `packaging/release-notes.md`.

## Publication

Publish the draft only after release authorization. Include every artifact listed in [RELEASING.md](../../RELEASING.md), especially `Diffy-macos-aarch64.dmg`, which the website's permanent download link uses. Verify the published manifest and download, then exercise the in-app update from 0.2.2 using an isolated installation.

Deploy the updated landing page with the established Cloudflare Pages Direct Upload workflow and its existing checkout configuration after 0.2.3 is available. Repository pushes do not deploy the website automatically. Verify desktop/mobile layout and the download link after deployment.

If a shipped issue requires rollback, republish the previous website build and prepare a newer corrective app version. Preserve existing release tags, updater keys, and archives.
