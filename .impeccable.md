## Design Context

### Users
Developers reviewing local Git changes, including changes produced by coding agents. Their primary job is reading diffs and moving quickly between projects.

### Brand Personality
Modern, minimal, lightweight. The app is called Differ. It should feel quiet, precise, and fast.

### Aesthetic Direction
Use the user-provided dark desktop screenshots as the visual reference, with familiar VS Code diff behavior. The latest direction replaces the top bar with colored squircle project icons down a compact left rail, like Discord. Show project names only on hover. Keep the compact alphabetical file list on the right and readable source in the center. A restrained warm yellow accent marks active navigation. Native window controls, pure-black surfaces without divider lines, no decorative cards or in-window app title.

### Design Principles
- Source is the main work surface; chrome stays subordinate.
- The left rail contains project icons only; do not invent agent entries before Herdr integration exists.
- Reading and whole-file staging/unstaging only: no approve, send, commit, or editing controls.
- No title or description above source. Put the short project path and branch at bottom left and spaced keyboard hints at bottom right.
- Use brief opacity transitions for project selection and gentle squircle-icon growth on hover; honor reduced motion and keep source stationary.
- Use bundled Commit Mono for source and all app-rendered navigation: Regular 13 px, Medium 14 px headings, and 12 px footer hints. Disable programming ligatures.
- Preserve keyboard access, selection, copying, and bounded scrolling.
- Wrap long source lines; modified files split 40/60 to favor the new version. Added files use a single full-width pane, even in Split mode.
